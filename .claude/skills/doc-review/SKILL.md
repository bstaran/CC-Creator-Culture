# /doc-review

대상: $ARGUMENTS

목적은 **읽기 쉬운 문장**을 만드는 것이다. 내용이 맞는지, 설계가 옳은지는 이 단계에서 다루지 않는다.

## 1. 대상 정하기

- **사람이 읽는 문서만** 대상이다. `.claude/` 아래 파일(스킬, 에이전트 지침), `CLAUDE.md`, 모델 프롬프트(`scripts/ai/prompts/`)는 제외한다. 이런 지침 문장은 Claude가 직접 다듬는다.
- 인자가 비어 있으면 스크립트가 현재 브랜치에서 바뀐 대상 문서를 찾는다(`origin/dev` 기준, 커밋하지 않은 변경 포함).
- 인자로 파일을 주면 바뀐 대상 문서에 더해 그 파일도 본다(`--only`면 그 파일만). PR 본문, 이슈 본문처럼 파일이 아닌 글은 스크래치 디렉터리에 임시 파일로 저장한 뒤 함께 넘긴다.
- 비밀 값 파일은 스크립트가 거부한다.

## 2. 교정받기(한 번에)

PR을 만들기 직전에 **대상 문서와 PR 본문을 한 번에** 넘긴다. 문서를 고칠 때마다 돌리지 않는다.

```bash
python3 scripts/ai/doc-review.py <PR 본문 파일>              # 바뀐 대상 문서 + PR 본문
python3 scripts/ai/doc-review.py --only docs/x.md            # 지정한 파일만
python3 scripts/ai/doc-review.py --only --full docs/x.md     # 문서 전체 흐름을 봐야 할 때
```

- **바뀐 부분만 보낸다.** 기준은 그 문서를 마지막으로 교정한 내용이고, 없으면 `origin/dev`의 내용이다. 바뀐 줄과 앞뒤 3줄을 보내며, 새 파일과 PR 본문은 처음에는 전체를 보낸다.
- **묶어서 보낸다.** 여러 문서의 조각을 200줄 단위로 묶어 호출 1회에 보내고, 묶음끼리는 동시에 호출한다. `agy`는 호출마다 고정 비용(입력 약 1.1만 토큰, 약 10초)이 들기 때문이다.
- 기본 모델은 `gemini-4-neon-medium`이다. 문장을 더 꼼꼼히 봐야 하면 `--model gemini-4-neon-high`를 쓴다. 묶음 1개에 수십 초에서 몇 분이 걸리므로 Bash 타임아웃은 600초로 준다.
- 종료 코드 3(`status: skipped`)이나 `error`, `timeout`이면 교정 단계를 건너뛰고 그 사실만 보고한다. 이 단계 때문에 작업을 멈추지 않는다.

## 3. 반영 판단(Claude)

제안을 그대로 붙여 넣지 않는다. 항목마다 판단한다.

| 판단 | 기준 |
|---|---|
| 반영 | 뜻은 그대로이고 더 읽기 쉬워진다(번역투 제거, 긴 문장 분리, 중복 제거, 맞춤법, 띄어쓰기, 주술 호응). 정보가 같으면 줄 전체의 문장 구조를 바꾸는 제안(맥락 없는 도입문, 대상이 빠진 동사, 마침표로 끊긴 나열, 소설체를 고치는 제안)도 반영한다 |
| 보류 | 뜻이 달라진다, 정보가 더해지거나 빠진다, 코드, 경로, 식별자나 백틱 안의 내용을 건드린다, 마크다운 구조(표 열, 목록, 링크)를 깬다, 문서나 레포 전체에서 이미 굳어진 용어를 바꾼다, 취향 차이일 뿐이다 |

스크립트가 아래 제안은 미리 걸러 내고 개수만 `filtered`에 보여 준다(내용은 `--verbose`). 걸러 낸 제안은 판단하지 않는다.

| 사유 | 내용 |
|---|---|
| `original-not-found`, `not-sent-line`, `no-change` | 원문이 그 줄에 없거나, 보내지 않은 줄이거나, 바뀌는 것이 없다 |
| `middle-dot` | 제안에 가운뎃점이 있다 |
| `backtick`, `code-block` | 백틱 안 내용을 바꾸거나 빼거나 새로 넣는다(같은 식별자를 다시 쓰는 것은 허용), 코드 블록 안을 바꾼다 |
| `structure` | 줄 앞의 들여쓰기, 목록 기호, 제목 기호, 인용 기호가 바뀐다 |
| `table` | 표 행에서 열 구분(`\|`) 개수가 바뀐다 |
| `glossary` | 용어 사전(`scripts/ai/prompts/doc-review-glossary.txt`)의 표기를 다르게 쓰거나 없앤다(문장을 합쳐 같은 용어를 덜 쓰는 것은 허용) |

- 제안은 Edit로 한 줄씩 반영한다. 같은 줄에 여러 제안이 겹치면 함께 고려해 한 번에 고친다.
- `middle_dot_lines`에 나온 줄의 가운뎃점(`·`)은 제안과 상관없이 쉼표, 슬래시, 목록으로 고친다.
- 고친 뒤 마크다운 표의 열 수가 그대로인지 확인한다.

## 3-1. 교정 기록

- 교정이 끝나면 스크립트가 문서 내용의 해시를 "교정 완료" 상태로 자동 기록한다(`.git/ai-doc-review.json`, 커밋되지 않음). `agy`를 쓸 수 없거나 교정에 실패하면 "건너뜀"으로 기록한다.
- 제안을 반영해 내용이 바뀌었으면 수정을 마친 뒤 `python3 scripts/ai/doc-review.py --mark <파일 ...>`로 다시 기록한다. 교정을 받지 않은 문서에는 `--mark`를 쓰지 않는다.
- 기록할 때 그 내용도 함께 보관한다(`.git/ai-doc-review/`). 교정 뒤 문서를 다시 고치면 기록은 무효가 되지만, 다시 교정할 때는 **그 뒤에 바뀐 줄만** 보낸다.
- 같은 표기를 계속 잘못 제안하면 용어 사전에 추가한다.
- PR을 만들 때 hook이 이 기록을 확인한다(브랜치에서 바뀐 대상 문서와 `--body-file`로 넘긴 PR 본문). 기록이 없으면 `gh pr create`가 차단된다.
