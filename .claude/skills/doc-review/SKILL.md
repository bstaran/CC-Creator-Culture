# /doc-review

대상: $ARGUMENTS

목적은 **읽기 쉬운 문장**을 만드는 것이다. 내용이 맞는지, 설계가 옳은지는 이 단계에서 다루지 않는다.

## 1. 대상 정하기

- 인자로 파일을 받으면 그 파일만 본다.
- 인자가 비어 있으면 현재 브랜치에서 바뀐 마크다운 문서를 대상으로 한다.
  ```bash
  git diff --name-only origin/dev...HEAD -- '*.md'; git status --porcelain -- '*.md'
  ```
- PR 본문, 이슈 본문처럼 파일이 아닌 글은 스크래치 디렉터리에 임시 파일로 저장한 뒤 넘긴다.
- 코드 파일, 설정 파일, 비밀 값 파일은 대상이 아니다(스크립트가 비밀 값 파일을 거부한다).

## 2. 교정받기

```bash
python3 scripts/ai/doc-review.py <파일 ...>                 # 기본 모델: gemini-4-hydrogen-medium
python3 scripts/ai/doc-review.py --model gemini-4-neon-high <파일>   # 계획, 스펙처럼 중요한 문서(약 3분)
```

- Bash 타임아웃을 넉넉히 설정한다(파일 수 × 300초).
- 종료 코드 3(`status: skipped`)이나 `error`, `timeout`이면 교정 단계를 건너뛰고 그 사실만 보고한다. 이 단계 때문에 작업을 멈추지 않는다.

## 3. 반영 판단(Claude)

제안을 그대로 붙여 넣지 않는다. 항목마다 판단한다.

| 판단 | 기준 |
|---|---|
| 반영 | 뜻은 그대로이고 더 읽기 쉬워진다(번역투 제거, 긴 문장 분리, 중복 제거, 맞춤법, 띄어쓰기, 주술 호응) |
| 보류 | 뜻이 달라진다, 정보가 더해지거나 빠진다, 코드, 경로, 식별자나 백틱 안의 내용을 건드린다, 마크다운 구조(표 열, 목록, 링크)를 깬다, 문서나 레포 전체에서 이미 굳어진 용어를 바꾼다, 취향 차이일 뿐이다 |
| 보류(자동) | `flags`에 `original-not-found`(원문에 없는 문자열) 또는 `middle-dot`(제안에 가운뎃점)이 있다 |

- 제안은 Edit로 한 줄씩 반영한다. 같은 줄에 여러 제안이 겹치면 함께 고려해 한 번에 고친다.
- `middle_dot_lines`에 나온 줄의 가운뎃점(`·`)은 제안과 상관없이 쉼표, 슬래시, 목록으로 고친다.
- 고친 뒤 마크다운 표의 열 수가 그대로인지 확인한다.

## 3-1. 교정 기록

- 교정이 끝나면 스크립트가 문서 내용의 해시를 "교정 완료" 상태로 자동 기록한다(`.git/ai-doc-review.json`, 커밋되지 않음). `agy`를 쓸 수 없거나 교정에 실패하면 "건너뜀"으로 기록한다.
- 제안을 반영해 내용이 바뀌었으면 수정을 마친 뒤 `python3 scripts/ai/doc-review.py --mark <파일 ...>`로 다시 기록한다. 교정을 받지 않은 문서에는 `--mark`를 쓰지 않는다.
- 교정 뒤 문서를 다시 고치면 기록이 무효가 된다. 이때는 다시 교정을 받는다.
- PR을 만들 때 hook이 이 기록을 확인한다(브랜치에서 바뀐 `.md` 파일과 `--body-file`로 넘긴 PR 본문). 기록이 없으면 `gh pr create`가 차단된다.

## 4. 보고

```
## 문서 교정(<모델>)
| 파일 | 제안 | 반영 | 보류 |
|---|---:|---:|---:|

보류한 주요 제안(이유): ...
```

작업 상태 파일이 있으면 진행 로그에 한 줄로 남긴다(모델, 제안 수, 반영 수).
