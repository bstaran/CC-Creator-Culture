## 기준

- **기대 동작**: 컨트롤러가 제공하는 외부 경로는 세 환경 모두 그 컨트롤러가 있는 서비스로 라우팅된다.
  - `PATCH /api/v1/admin/products/{productId}/status` → product-service(세 환경)
  - `/api/v1/images/**` → product-service(세 환경)
- **근거**:
  - `ProductAdminCommandController.java:16` `@RequestMapping("/api/v1/admin/products")`(product-service)
  - `/api/v1/images` 핸들러는 product-service `ImageUploadController`에만 있다. dev, prod 설정은 이미 product-service로 보낸다(`gateway-dev.yaml:24`, `gateway-prod.yaml:17`)
- **현재 동작**: admin 상품 경로는 세 환경 모두 매칭되는 라우트가 없다. local은 `/api/v1/images/**`를 user-service로 보낸다(`gateway-local.yaml:20`).
- **완료 기준**: 재현 테스트(아래)가 수정 전 실패, 수정 후 통과. `:infra:gateway` 기존 테스트 모두 통과.
- **고정 파일**: `infra/gateway/src/test/java/com/sub9/gateway/route/GatewayRouteConfigTest.java`(15케이스: 버그 4, 회귀 11)
- **수정 전 실패(4/15)**:
  - `[local] PATCH /api/v1/admin/products/1/status`: 실제 매칭 라우트=없음
  - `[dev] PATCH /api/v1/admin/products/1/status`: 실제 매칭 라우트=없음
  - `[prod] PATCH /api/v1/admin/products/1/status`: 실제 매칭 라우트=없음
  - `[local] POST /api/v1/images/presigned-url`: 실제 매칭 라우트=user-service (lb://user-service)
