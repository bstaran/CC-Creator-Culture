# AI 작업 가이드(팀원용 초안)

AI(Claude Code)로 작업할 때 참고하는 안내서다. 전체 설계는 [plan.md](plan.md)에 있다.

## 시작하기

1. **Claude Code 실행**: 레포 루트에서 연다. AI가 `CLAUDE.md`(루트, 서비스별, `infra/`)를 자동으로 읽어 빌드 명령, 계층 규칙, 금지 사항을 파악한 상태로 작업을 시작한다.
2. **Java 환경 설정**: `java`가 PATH에 없으면 셸 설정에 JDK 21의 `JAVA_HOME`을 지정한다. 작업 종료 시 컴파일 검증(hook)이 이 JDK를 사용한다.
3. **Python 확인**: hook 스크립트 실행에는 `python3`가 필요하다.

## 작업 요청하기

무엇을 하든 분류부터 시작한다.

```text
/triage 주문 취소 시 쿠폰이 복구되지 않는다
/triage #123
```

`/triage`를 실행하면 다음 항목을 정리해 제안한다.

- **트랙 분류**: 리팩토링, 버그 수정, 기능 개발, 조사/문서, 인프라/배포, 성능
- **먼저 고정할 기준**, **대상 모듈**, **위험 요소**

분류 결과를 확인한 뒤 **이슈로 등록 / 지금 진행 / 보류** 중 하나를 선택한다. AI는 사용자 승인 없이 이슈나 브랜치를 만들지 않는다.

> 기록을 남기거나 다른 담당자에게 맡길 작업이라면 GitHub에서 **🤖 AI 작업 요청** 이슈 양식을 작성한다.

### GitHub에서 `@claude`로 요청하기

1. **분류**: 이슈에 `@claude`를 처음 남기면 AI가 `/triage`로 분류하고, 트랙, 기준, 다음 단계를 댓글로 남긴다. 이 단계에서는 코드, 브랜치, 라벨을 바꾸지 않는다.
2. **진행**: 분류 결과를 확인한 뒤 `@claude 진행해`라고 남기면, AI가 트랙 라벨을 붙이고 트랙 스킬로 처리해 PR을 연다. 기능 개발은 스펙 초안까지만 쓰고, `spec: approved` 라벨은 사람이 붙인다.
3. **PR 수정**: 열린 PR에 `@claude`로 수정을 요청하면 AI가 고치고 검증 결과를 댓글로 남긴다.

CI에는 Gemini 도구가 없어서 문서 교정과 Gemini 코드 리뷰는 건너뛴다. 필요하면 로컬에서 `/doc-review`, `/gemini-review #번호`를 실행한다. 머지, 승인 리뷰, `spec: approved` 라벨, `dev`/`main` 직접 push는 hook이 막는다.

## 트랙별 역할 분담

| 트랙 | AI가 먼저 하는 일 | 사람이 하는 일 |
|---|---|---|
| **리팩토링** | 특성 테스트로 현재 동작 고정 | 리뷰, 머지 |
| **버그 수정** | 실패하는 재현 테스트 작성 | 리뷰, 머지 |
| **기능 개발** | 스펙 초안 작성 | **스펙 승인**(`spec: approved` 라벨), 리뷰, 머지 |
| **조사/문서** | 근거(`파일:줄`)를 붙여 답변 | 내용 확인 |
| **인프라/배포** | 변경 초안, fmt/validate/test | **plan 확인, apply, 배포**(CI에서 실행) |
| **성능** | 측정 계획, 기준선 비교 | 측정 계획 승인, 결과 판단 |

## 스킬 목록

| 스킬 | 사용 시점 | 하는 일 |
|---|---|---|
| `/triage <요청>` | 모든 작업의 시작 | 트랙 분류, 기준과 리뷰어 결정, 다음 단계 제안 |
| `/bugfix #번호` | 버그 이슈 | 재현 테스트 고정 → 수정 → 검증 → 리뷰 → PR |
| `/refactor-task #번호` | 리팩토링 이슈 | 특성 테스트로 동작 고정 → 리팩토링 → 검증 → 리뷰 → PR |
| `/characterize <대상>` | 고치기 전 동작 고정 | 현재 동작을 테스트로 고정 |
| `/refactor-audit [서비스]` | 정기 점검, 주간 리포트 후보 등록 | 서비스별 진단으로 리팩토링/버그 후보 목록 작성, 주간 리포트에서 체크한 후보 등록 |
| `/spec <요청>` | 기능 개발 시작 | 스펙 초안(완료 조건 AC, API/이벤트/DB 변경) 작성, 승인 요청 |
| `/feature #번호` | `spec: approved` 이후 | 요구사항 테스트 고정 → 구현 → 검증 → 리뷰 → PR |
| `/infra-change #번호` | 인프라/배포 변경 | 예상 plan 요약, 로컬 검증, 리뷰 → PR(plan과 적용은 사람이 CI에서 실행) |
| `/perf-check #번호` | 성능 회귀 확인, 개선 | 측정 계획 확인 → 로컬 스택에서 기준선과 비교 |
| `/doc-review [파일]` | 문서/PR 본문 작성 후 | 다른 모델(Gemini)로 문장 교정, 반영 여부 판단 |
| `/gemini-review [#번호]` | PR 직전, 열린 PR 리뷰 | 다른 모델(Gemini)로 코드 2차 리뷰, PR이면 오탐을 뺀 지적을 리뷰 코멘트로 게시 |

## AI가 할 수 없는 작업(hook 차단 대상)

- **비밀 값 접근**: `.env`, `*.tfvars`, `backend.hcl`, state 파일 읽기
- **인프라 적용 및 배포**: `terraform plan`, `apply`, `destroy`, `state` 등 원격 상태 접근 및 적용 명령, 배포 워크플로우 실행
- **원격 저장소 직접 변경**: `origin` 외 원격 push, `dev`/`main` 직접 push, force push
- **안전장치 훼손**: 기존 Flyway 마이그레이션 수정, `-x test`로 테스트 건너뛰기

> **차단 메시지가 나온 경우**
> 규칙을 우회하지 말고 차단 사유를 확인한다. 필요한 작업까지 규칙에 막힌다면 `.claude/hooks/`를 수정하는 PR을 올린다.

## 주간 리포트

매주 월요일 09:00(KST)에 `report: weekly` 라벨이 붙은 **주간 리포트 이슈**가 자동으로 만들어진다. 지난 7일의 지표(머지된 PR, 이슈, 동결된 계층 위반)와 바뀐 코드에서 찾은 이슈 후보가 들어 있다.

- 등록할 후보를 체크하고 리포트에 `@claude 체크한 항목을 이슈로 등록해`라고 댓글을 남긴다. 체크하지 않은 후보는 등록되지 않는다.
- 절차와 지표 정의는 [playbooks/operations.md](playbooks/operations.md)에 있다.

## 진행 상태 확인

큰 작업에서는 `docs/ai-system/tasks/<이슈번호>.md`에 계획, 진행 로그, 결정 사항, 남은 일이 기록된다. 세션이 끊기거나 다른 사람이 이어받을 때는 이 파일부터 읽는다.

## 머지

머지는 항상 도메인 담당자가 한다. AI가 만든 PR도 사람이 만든 PR과 같은 기준으로 리뷰한다.
